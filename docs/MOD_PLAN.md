### 0.3 需要你注意的提醒（重要，请先看）

1. **单端口会让测试数据和真实数据混在一起。** PRD 里只有 `localhost:5173`，浏览器按地址隔离数据，所以你现在开发和真正使用很可能是同一个库。改造期间必须分开：
   - 真实使用：冻结在基线版本，用构建产物跑在 5173（`vite build` 后 `vite preview --port 5173 --strictPort`）。
   - 开发改造：另开分支，用另一个端口（建议 5180，`strictPort`），它是一个**全新的空库**，用备份文件导入测试数据。
   - 如果你现在是用 `npm run dev` 在 5173 上真实使用，开发时改动会直接影响你用的版本。
2. **每轮上线前必须先备份。** 新版第一次在 5173 打开时会对真实数据做迁移，迁移出错就是真实数据出错。流程见第 10 节。
3. **备份版本号会卡住旧备份。** PRD 要求版本不对就拒绝导入。数据库升到 2、3 后，如果只认当前版本，你在基线版本时导出的备份（版本 1）就导不进去了。规则要改成：**接受版本小于等于当前的备份并自动升级；版本更大的拒绝并提示"请先升级应用"**。这条要有测试。
4. **新表要加入"1 小时回收"和导出。** 新增的表（健身项目、错题、错题图片）都要：被导出；被软删除回收覆盖；回收时连带清理关联图片。"所有表都被导出"的测试若存在要更新，不存在要补上。
5. **改完表结构后，开发库要清掉重来。** 同一个版本号下再加表，已经打开过的开发库不会重新执行升级。遇到这种情况，在 5180 清空站点数据，再导入基线备份即可。
6. **你之前要求的"待办拖拽排程"，这份 PRD 推迟了，这一轮的 11 项里也没有它。** 书架拖动会引入拖拽库，之后补做待办拖拽成本会低很多。需要的话告诉我，我加到计划里。
7. **手机适配只是窄屏布局。** 数据仍只在电脑浏览器里，手机打开是一个空应用；用局域网地址访问时浏览器不算"安全环境"，部分功能（生成 ID、申请持久存储）可能失效。这一轮不做手机录入和同步。
8. **文本导出不能碰"上次备份时间"。** 分析导出不是备份，不能更新备份时间，也不能让"超过 7 天未备份"的提醒消失。
9. **PRD 要先同步。** PRD 写着"改动需先更新本文档"。这一轮改完后，PRD 要升到 v1.3，改动清单在第 12 节，我可以代写。

## 1. 所有任务通用的规则（写进 AGENTS.md）

1. 一次只做一个任务编号；做完能运行、`npm run check` 全绿、提交一次，提交信息写任务编号。
2. 每个任务先读 `docs/CURRENT_STATE.md`，核对本任务的"假设"。**不一致先停下报告，不要自己决定。**
3. 新字段、新表一律 `snake_case`；表名、文件名沿用 `CURRENT_STATE.md` 里的现有风格。
4. **改表结构**必须：新增数据库版本和迁移；旧数据不丢；新表进入导出和 1 小时回收；备份 `schema_version` 同步升级；**旧版本备份仍可导入**；有迁移测试。同一轮的改动合并成一个新版本号，已上线的版本不再修改。
5. 保存规则按 PRD 2.5：弹窗表单点"保存"写入；页内编辑区和一键动作即时自动保存。**不新增路由拦截弹窗，不新增"保存"按钮。**
6. 删除一律软删除并带 5 秒撤销条；关联对象删除遵守 PRD 5.10（计时中禁止删除、历史靠名称快照显示"原名称（已删除）"）。
7. 取当前时间必须用项目里统一的时钟函数（盘点确认名称，例如 `now()`），不直接用 `Date.now()` 或 `new Date()`；日期统计按逻辑日期。
8. 纯逻辑（统计、聚合、导出文本、排序）先写测试再实现。
9. 页面不直接操作数据库，必须经过现有的服务层（盘点确认结构）。
10. 运行时不联网，不引入 CDN、外部字体和图标。新增依赖必须先说明理由，经我批准。
11. 快捷键保持 PRD 的三个（`N`、`Space`、`Esc`），不新增。计时结算弹窗不能被 `Esc` 或点遮罩关闭，新增的任何弹窗都不得破坏这条。
12. 每个任务完成后更新 `docs/CURRENT_STATE.md`。
