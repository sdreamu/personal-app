# 产品需求文档（PRD）：Evan的专属APP

个人学习生活 App · 第一版（v1.2 定稿版，已完成技术走查与逻辑闭环）
状态：设计已确认，可直接用于数据结构生成与代码开发。
用途：后续开发的唯一依据。开发中发现冲突，以本文档为准，改动需先更新本文档。

---

## 1. 产品目标和使用场景

### 1.1 一句话

一个只在我自己电脑浏览器里运行的个人 App，把**学习**（读书、科目、专注计时）和**生活**（饮食喝水、健身、娱乐）放在同一个地方记录，用**计划**安排一天，用**复盘**回看一天。

### 1.2 目标

1. 每天打开它记录和安排，**连续使用一周以上**。
2. 记一笔足够快：喝水、计时一键完成，其余记录不超过 3 次点击。
3. 数据留在这台电脑上，刷新、关闭网页、重启电脑都不丢，并且可以备份和恢复。
4. 每个模块有符合自己场景的功能，不是同一个任务列表换名字。

### 1.3 使用者与环境

- 使用者：我一个人。
- 设备：同一台电脑，桌面浏览器（验收以 Chrome 或 Edge 最新版为准）。
- 使用频率：每天多次短暂打开，早上看计划，白天计时和打卡，晚上复盘。

### 1.4 典型的一天

| 时间 | 场景 |
|---|---|
| 早上 | 打开首页，看到昨天写下的"今天最重要的一件事"和今天的计划；把未完成的昨日待办一键顺延 |
| 白天 | 按计划开始读书或学习科目的计时；结束时写一句收获、更新读到的页码；顺手记一餐、点喝水 |
| 下午 | 去健身页按当天训练模板逐组打卡 |
| 晚上 | 记录玩了多久游戏，看额度；打开复盘，查看自动汇总，打分并写感想，定下明天最重要的一件事 |

### 1.5 明确的限制

只在本机浏览器运行。**不需要**登录、联网、云数据库、部署、手机端。第一版**不含** AI 功能（AI 需要联网，与本地运行冲突）。

### 2.3 顶栏

- **软件名称**：侧栏顶部和浏览器标签页标题均为"Evan的专属APP"。
- **日期切换**：前一天、后一天、回到今天。查看非今天时，内容区顶部显示淡色提示"你正在查看 10月20日"，并可补记。
- **计时胶囊**：有计时进行中或待结算时在任何页面可见。进行中显示"对象名称 + 已用时间"；待结算时高亮显示"⏱ 待结算（点击处理）"。点击胶囊时：若当前为学习计时（书/科目）则跳转到 `#/study/timer`，若当前为娱乐计时则跳转到 `#/life/play`。
- **保存状态提示**：顶栏右侧常驻轻量状态提示（默认显示"已自动保存 ✓"，写入时短暂显示"保存中..."，写入失败时显示顶部红条与导出备份入口）。

### 2.4 全局规则与保存机制

| 规则 | 说明 |
|---|---|
| 逻辑日期 | "今天"按设置里的一天起点计算（默认 04:00）。凌晨 2 点的记录归属前一天。每条记录同时保存精确时间和逻辑日期 |
| 起点修改 | 修改一天起点只影响之后的新记录，已有记录的逻辑日期不重算 |
| 周起点 | 一周从周一开始，所有"本周"统计按此计算 |
| 混合自动保存 | **弹窗表单点保存写入，页内编辑与一键动作即时自动保存**（详见 2.5） |
| 删除与撤销 | 点击删除立即标记软删除（`deleted_at`），顶部提示"已删除，撤销"（约 5 秒内可恢复）；只有"清空所有数据"需要二次确认 |
| 空状态 | 每个页面无数据时显示一句引导和一个主按钮，不留空白 |
| 地址刷新 | 刷新后停留在当前页面、当前选中的逻辑日期 |
| 快捷键 | 仅三个：`N` 当前页新增一条；`Space` 计时器页开始/暂停；`Esc` 关闭普通弹窗（计时结束结算弹窗除外） |
| 同时只有一个计时 | 全局（含读书、科目、娱乐）同一时间只能有一个计时进行或处于待结算状态，未处理完前不能开启新计时 |

### 2.5 保存规则细则（弹窗确认 + 页内即时自动保存）

已保存的数据，刷新、关闭网页、重启电脑都不丢。不设全局路由离开拦截弹窗。

| 类型 | 规则 | 适用场景 |
|---|---|---|
| 弹窗表单与单框快捷操作 | 底部有"保存"和"取消"按钮；点"保存"或按回车才写入，点"取消"或按 `Esc` 放弃。单行快捷输入（如更新页码、饮食输入）按回车或点"✓"立即保存 | 新增/编辑计划项、安排时间、新增/编辑书、新增/编辑科目、新增/编辑摘录、手动补记记录、结束计时结算弹窗 |
| 页内编辑区 | 改动后立即自动写入本地数据库（多行文字输入采用 300ms 防抖自动保存，切换页面或组件卸载前立即触发写入，确保刷新不丢） | 复盘页（评分、心情、精力、三栏文字）、设置页各项配置、健身页（周计划模板编辑、当天训练组数/重量/次数修改） |
| 一键动作 | 点击立即写入生效 | 勾选计划完成、喝水 +1/-1、开始/暂停计时、移到明天、一键顺延、删除与撤销、点击饮食常吃快捷项、健身勾选某组完成 |

## 3. 首页的内容结构

首页**只读汇总，自己不存任何数据**，所有数字来自各模块。卡片可点击跳转，部分卡片带可直接操作的按钮。

### 3.1 顶部提示条

按优先级显示，**最多同时显示 2 条**：

| 优先级 | 提示 | 点击后 |
|---|---|---|
| 1 | 有未结束或待结算的计时 | 去对应计时页面处理 |
| 2 | 昨天还没复盘 | 去复盘页补写 |
| 3 | 昨天有 N 项未完成（且尚未顺延） | 一键顺延到今天 |
| 4 | 超过 7 天没有备份 | 去设置页导出 |

另有一条**常驻**的"昨天定下的最重要一件事"（昨日复盘填写了才显示）：
- 若尚未加入今日待办，旁边显示"加入今日待办"按钮；点击后自动在今日计划生成一条待办，并将昨日复盘的 `mit_added_to_plan` 置为 `true`。
- 若已加入，按钮显示为"已加入今日待办 ✓"并处于禁用状态，防止重复添加。

### 3.2 六张卡片

| 卡片 | 显示内容 | 可直接操作 | 点击跳转 |
|---|---|---|---|
| 今日计划 | 已完成 / 总数；下一个未完成的时间块 | 勾选下一项为完成 | 计划 |
| 学习 | 今日学习时长 / 目标，进度条 | 开始计时 | 计时器 |
| 阅读 | 在读书籍及进度（最近阅读的一本为主） | 继续阅读（预选这本书进入计时） | 书详情 |
| 喝水 | 已喝 / 目标 ml | +1 杯 | 饮食 |
| 运动 | 今日训练类型和是否完成；休息日显示"今天休息" | 去训练 | 健身 |
| 娱乐 | 已用 / 额度，剩余分钟 | 无（防止首页变得杂乱） | 娱乐 |

### 3.3 首页规则

- 首页始终显示**今天**（不随顶栏日期切换变化；切换到其他日期时，点首页会回到今天）。
- 新用户（设置里还没有目标）首页第一张卡片显示"先去设置里定今日目标"的引导。
- 没有在读的书时，阅读卡片显示"去书架添加一本书"。

## 5. 每个模块第一版最必要的数据和操作

通用字段（每种数据表都有）：`id`、`created_at`、`updated_at`、`deleted_at`（软删除时间戳，未删除为 `null`）。

### 5.1 计划

**计划项**（待办和时间块是同一种数据：有起止时间就是时间块，没有就是待办）

| 字段 | 说明 |
|---|---|
| 标题 | 必填 |
| 日期 | 逻辑日期（`YYYY-MM-DD`） |
| 开始、结束时间 | 可空（格式 `HH:mm`）；有则显示在左侧时间轴，无则显示在右侧待办清单 |
| 分类 | 内置 `学习` / `生活` / `其他`，或用户在设置中新增的自定义分类 |
| 关联对象 | 可空；关联对象类型（书/科目）、对象 ID 及**对象名称快照（`target_title`）**（仅学习类） |
| 完成状态、完成时间 | 布尔值及完成时间戳 |
| 顺延状态與来源 | `rollover_from_date`（若由顺延产生，记录原日期）；`is_rolled_over`（昨日未完成项已被顺延到今天时标记为 `true`，防止重复顺延） |

**操作与业务规则**：
1. **新增与编辑**：按 `N` 或点按钮弹出表单，填写后点"保存"写入。
2. **安排时间（不做鼠标拖拽）**：对右侧无时间待办点"安排时间"（或在编辑表单中设置），可选择开始时间和结束时间（提供快捷时长按钮：30分钟 / 45分钟 / 60分钟 / 90分钟），保存后移入左侧时间轴；清空起止时间则变回普通待办。
3. **跨一天起点的时间轴规则**：时间轴从设置里的"一天起点（默认 04:00）"开始，覆盖 24 小时（如今日 04:00 至次日 04:00）。所有时间块的起止时间在底层统一换算为**距离当天起点的偏移分钟数（`0 ~ 1440`）**进行校验、排序与渲染（例如起点 04:00 对应 `0`，23:00 对应 `1140`，次日 01:00 对应 `1260`）。要求 `0 <= 开始偏移 < 结束偏移 <= 1440`，时间块不得跨越一天起点边界。
4. **时间重叠**：两个时间块存在重叠时，并排显示并给出重叠提示图标，不阻止保存。
5. **移到明天 vs 一键顺延昨日未完成**：
   - **移到明天**（主动改期）：直接将该未完成项的 `日期` 改为明天，从今天列表中消失。
   - **一键顺延昨日未完成**（次日补救）：保持昨日原记录留在昨天（保留昨日计划分母，确保昨日复盘统计不失真，仅将其 `is_rolled_over` 标为 `true`），同时在今天**克隆生成对应的新待办**（清空起止时间，记录 `rollover_from_date = 昨天`）。
6. 页面顶部显示今日完成进度，并显示一条只读的"今日训练：腿 [去训练]"（来自健身模块，不生成待办）。

### 5.2 读书

**书**：书名（必填）、作者、总页数（必填，正整数）、当前页（默认 0）、状态（想读/在读/读完）、封面色（随机生成）、开始日期、读完日期。
**摘录**：所属书 ID、页码（必填，正整数）、摘录内容（必填）、我的想法（可选）。

**操作与业务规则**：
1. 添加书、编辑、改状态、删除；新增、编辑、删除摘录（按页码从小到大排序）。
2. **更新页码与阅读增量记录**：在书架或书详情页直接手动修改"当前页"时，除了更新书的当前页码，若新页码大于原页码，后台自动生成一条当天逻辑日期的学习记录（对象为该书，时长为 0，起始页码为原页码，结束页码为新页码，本次阅读页数为两者差值，来源为`手动更新页码`），确保复盘页能统计到当日阅读页数。进度达到 100%（当前页 = 总页数）时弹窗提示"标记为读完？"。
3. **开始阅读计时**：跳转 `#/study/timer` 并预选此书。
4. **手动补记阅读记录**：在书详情页可手动补记一条阅读记录（逻辑日期、时长分钟、读到页码、收获）。
5. **预计剩余时间显示规则**：仅当 `累计阅读时长 ≥ 2 小时` 且 `当前页码 > 0` 且 `状态 !== 读完` 时显示预计剩余时间；计算公式为：`预计剩余时间 = (总页数 - 当前页) × (累计阅读时长 ÷ 当前页)`。不满足条件时不显示。
6. **封面**：不使用图片，用书名首字加随机底色。

### 5.3 科目

**科目**：名称（必填）、每周目标时长（分钟）、截止日期（可选）、是否归档（布尔值）。

**操作与业务规则**：
1. 添加、编辑、归档/取消归档、删除；查看该科目的历史学习记录；手动补记一条学习记录（日期、时长分钟、收获）；开始计时（跳转 `#/study/timer` 并预选此科目）。
2. 显示：本周已学时长 / 周目标时长，截止日期倒计时（还剩 X 天），本周（周一至周日）每日学习时长的 7 根柱状图。

### 5.4 计时器与学习记录

**学习记录**（书和科目共用一种数据表）：
- 字段：对象类型（`book` / `subject`）、对象 ID、**对象名称快照（`target_title`）**、开始时间、结束时间、时长（秒，不含暂停）、收获（可选）、**起始页码（`start_page`，仅书）**、**结束页码（`end_page`，仅书）**、**本次阅读页数（`pages_read = max(0, end_page - start_page)`，仅书）**、来源（`timer` 计时 / `manual` 手动补记 / `page_update` 手动更新页码）、逻辑日期（按开始时间计算）。

**进行中的全局计时**（全局单实例，只会有一条）：
- 字段：计时类型（`book` / `subject` / `entertainment`）、对象 ID（娱乐计时为娱乐内容名称）、对象名称、关联计划项 ID（可空，从计划时间块启动时记录）、模式（正计时 `stopwatch` / 倒计时 `countdown`）、倒计时设定长度（秒，默认 25 分钟即 1500 秒）、开始时间戳、累计暂停时长（秒）、当前是否暂停、暂停开始时间戳、结束时间戳（`ended_at`，点击"结束"后写入，表示处于**待结算**状态）。

**操作与保护规则**：
1. **入口分离，状态共用**：
   - `#/study/timer` 仅用于选择"在读的书"或"未归档的科目"进行学习计时（未选择对象时无法开始并提示先选择）。
   - 娱乐计时直接在 `#/life/play`（娱乐页）发起和控制。
   - 两者共用同一个全局计时状态机和顶栏计时胶囊，任何时刻全局只能有一个计时存在。
2. **结算与"待结算"全局阻塞状态**：
   - 点击"结束"后，计时立即停止，记录 `ended_at` 进入**待结算**状态，并弹出结算弹窗。
   - **学习计时结算弹窗**：显示本次有效时长；输入收获（可跳过）；若是书，默认带出书的当前页作为起始参考，询问"读到第几页"（必填，默认填入当前页）。点击"保存"才正式生成学习记录（自动计算 `pages_read`）并更新书的当前页码；点击"丢弃"则清空本次计时不留记录。
   - **娱乐计时结算弹窗**：显示本次折算分钟数（向上取整，支持微调确认），点击"保存"生成娱乐记录，点击"丢弃"则放弃。
   - **防逃逸阻塞**：结算弹窗**不可通过按 `Esc` 或点击背景遮罩关闭**（必须明确点"保存"或"丢弃"）。若用户在弹窗打开时刷新网页、关闭重开或通过改地址栏切到其他页面，顶栏计时胶囊高亮显示 `⏱ 待结算（点击处理）`，且禁止开启任何新计时；回到计时页或点击胶囊立即重新弹出该结算弹窗，时长保持不变。
3. **异常与边界保护**：
   - **不足 1 分钟**：有效计时不足 60 秒点击结束时，先询问"计时不足 1 分钟，是否直接丢弃？"（可选"直接丢弃"或"继续结算保存"）。
   - **倒计时到点**：倒计时归零时浏览器标签页标题闪烁并弹出提示，可选"再来一轮（先结算本轮并立即开启下一轮）"或"结束（进入结算弹窗）"。
   - **刷新与超时恢复**：刷新或关闭浏览器重新打开后，根据时间戳自动恢复计时进度；若检测到进行中的计时已超过 12 小时，弹窗让用户选择"继续计时 / 结束并手动修改时长 / 直接丢弃"。
4. **计划联动**：若本次计时是从计划页的时间块点击"开始"进入的，结算保存后顺带询问"是否将关联的计划时间块标记为完成？"。

### 5.5 饮食

**餐食记录**：逻辑日期、餐次（早/午/晚/加餐，或自定义餐次）、内容文字、感受（吃饱/没吃饱/吃多了，可选）。
**喝水记录**：逻辑日期、毫升数（正数或负数）、记录时间。

**操作与业务规则**：
1. 每餐区点 `+` 输入一行文字按回车即添加（可多项）；支持编辑、删除。
2. **常吃快捷项**：**按餐次（早/午/晚/加餐）独立统计**该餐次历史记录中出现频次最高（频次相同取最近录入）的**前 8 项**，作为快捷标签展示，点击一次立即添加到当天该餐次。
3. **复制昨天这一餐**：一键把昨天同一餐次的所有餐食项复制到今天该餐次。
4. **喝水打卡**：点 `+1 杯` 增加一杯水量，点 `-1 杯` 扣减一杯水量（单日总水量保底为 0 ml，杯量来自设置）。显示圆点进度（每满一杯亮一个圆点）。不计算热量。

### 5.6 健身

**每周计划**：周一到周日各自的训练类型（或"休息"）和动作模板（动作名称列表）。
**训练记录**：逻辑日期、训练类型、动作列表（每个动作含若干组：重量 kg、次数、是否完成）、用时（分钟，可手改）、是否完成（布尔值）。

**操作与业务规则**：
1. **即时自动保存**：编辑周计划模板、在当天训练中逐组勾选完成、修改重量或次数、添加/删除临时动作，全部**即时自动保存**，无需手动点击保存按钮。
2. **自动带入历史数值**：打开当天健身页时，若当天尚无训练记录，根据星期几自动带出周计划模板；每个动作的默认组数、重量和次数自动带入**该动作名称在最近一次已完成训练中的数值**（无历史则默认 3 组）。动作名称输入时提供历史动作名自动补全提示。
3. **休息日与临时训练**：周计划为"休息"的日期打开健身页显示"今天休息"，同时提供"开始临时训练"按钮。
4. **完成训练与用时计算**：点击"完成训练"将当天训练标记为已完成。若用户未手动输入"用时（分钟）"，系统自动计算当天首次勾选动作组到点击完成训练的时间差（分钟）；若差值不足 1 分钟或一次性勾完，默认填入 `30` 分钟，用户可随时手动修改。支持查看历史训练记录列表。

### 5.7 娱乐

**娱乐记录**：逻辑日期、内容名称（如游戏名/视频）、分钟数（正整数）、来源（`timer` 计时 / `manual` 补记）。

**操作与业务规则**：
1. 页面内置娱乐计时器控制区（输入或从历史标签选择内容名称 → 开始 / 暂停 / 结束计时，共用全局单实例计时状态），也支持直接手动补记分钟数；支持编辑、删除。
2. 显示：今日娱乐额度进度条（已用 / 额度 / 剩余分钟），超额后进度条变红并提示"今日娱乐额度已用完"，但不阻止继续记录；显示本周累计娱乐时长。

### 5.8 复盘

**复盘记录**：逻辑日期、今日评分（1 到 5 星）、今日心情（1 到 5，对应 😞 😕 😐 🙂 😄）、今日精力（1 到 5，对应 5 格能量条）、做得好的、要改进的、明天最重要的一件事、**最重要一件事是否已加入次日待办（`mit_added_to_plan`，默认 `false`）**。

**操作与计算口径**：
1. **评分与文字即时自动保存**：今日评分、心情、精力支持点击选中，**再次点击已选中项可取消选择**（三项均可留空）；三栏文字输入采用防抖自动保存，刷新不丢。
2. **自动汇总指标及严格计算公式**（只读，实时聚合当天逻辑日期的有效数据）：
   - `计划完成数`：当天计划项中 `已完成数 / 总数`。
   - `学习时长及目标`：当天所有学习记录（书 + 科目）的 `时长总和 / 设置中的每日学习目标`。
   - `阅读页数`：当天所有书籍学习记录（含计时结算与手动更新页码）的 `pages_read（本次阅读页数）` 之和。
   - `喝水量及目标`：当天喝水记录毫升数总和 / 设置中的每日喝水目标。
   - `是否运动`：当天是否有标记为"已完成"的健身训练记录（显示训练类型及用时，或"未运动"）。
   - `娱乐时长及额度`：当天娱乐记录分钟数总和 / 设置中的每日娱乐额度。
   - `计划学习时长与实际的差值`：
     - `计划学习时长` = 当天分类为"学习"且设置了起止时间的所有时间块时长直接相加（不含无起止时间的待办，重叠时间段不合并扣减）。
     - `差值` = `当日实际学习总时长 - 当日计划学习时长`（正数显示为"+X 分钟（超额完成）"，负数显示为"-X 分钟（未达计划）"）。
3. **历史列表与回看**：展示历史复盘列表（日期、星级、心情、精力、一句话摘要）；最近 14 天内未填写复盘的过去日期用灰点标记，点击可切换至该日期补写。

### 5.9 设置

| 分组 | 内容与规则 |
|---|---|
| 每日目标 | 学习时长目标（默认 120 分钟）、喝水目标（默认 2000 ml）和每杯容量（默认 250 ml）、娱乐额度（默认 60 分钟） |
| 一天的起点 | 默认 `04:00`（整点或半点选择，修改后仅对新记录生效） |
| 分类管理 | 计划分类（内置 `学习`、`生活`、`其他` **不可删除或改名**，可新增/编辑/删除自定义分类）、训练类型（可增删改）、餐次（内置 `早`、`午`、`晚`、`加餐` **不可删除或改名**，可新增自定义餐次） |
| 外观 | 浅色 / 深色模式（切换立即生效并持久化） |
| 数据管理 | 导出备份、导入备份、清空所有数据、上次备份时间显示 |

设置页所有配置项修改后立即生效并自动保存。

### 5.10 关联对象删除的防呆与级联规则

1. **计时中防删**：当前正在计时（或处于待结算状态）的书籍或科目，禁止删除或归档，点击时提示"该项正在计时中，请先结束计时"。
2. **保留历史快照**：删除一本书或一个科目时，仅级联软删除该书下的"摘录"；过去已生成的"学习记录"和"计划项"**不删除**，依靠冗余字段 `target_title` 显示为 `原名称（已删除）`，确保历史复盘与周统计的学习总时长不会因删书/删科目而被篡改。

## 6. 首页、今日计划和各模块之间的关系

### 6.1 总原则

**每个数据只在一个地方录入，其他地方只读引用。** 例如喝水只在饮食页（或首页的 +1 杯按钮，本质是同一个动作）写入，复盘只读不写。

### 6.2 关系表

| 从 | 到 | 关系 |
|---|---|---|
| 首页 | 所有模块 | 只读汇总；"+1 杯"写入喝水记录；"开始计时"跳转计时器 |
| 计划 | 读书/科目 | 学习类时间块可关联书或科目；点"开始"进入计时器并预选 |
| 计时器 | 计划 | 结束保存后可顺手标记关联的时间块完成 |
| 计时器 | 读书 | 结束保存后更新页码，生成含阅读页数增量的学习记录 |
| 计时器 | 科目 | 生成学习记录，计入周目标进度 |
| 健身 | 计划 | 计划页顶部只读显示今日训练提示（不自动生成待办） |
| 复盘 | 首页、计划 | "明天最重要的一件事"次日显示在两处，可一键加入待办（防重复） |
| 设置 | 全部 | 目标、额度、杯量、一天起点、分类 |
| 全部 | 复盘 | 复盘自动汇总所有模块当天数据 |

### 6.3 数据流示意

```
设置 ──(目标/起点/分类)──▶ 所有模块
计划 ◀──关联──▶ 计时器 ──▶ 学习记录 ──▶ 读书页码 / 科目周进度
饮食、健身、娱乐 ──┐
计划、学习记录   ──┼──▶ 首页（只读）
                  └──▶ 复盘（只读汇总）──▶ 明日首页/计划提示
```

娱乐与学习第一版**不互相联动**（如"学够才能玩"留到以后）。

## 7. 本地数据文件、备份和恢复要求

### 7.1 存储与端口锁定

- **主存储**：浏览器内置的本地数据库（IndexedDB），整个 App 使用同一个数据库（`evan_personal_app_db`）。
- **固定访问地址与严格端口锁定**：必须通过固定的本地地址打开（默认 `http://localhost:5173`），**不得用 `file://` 直接打开网页，也不得随意更换端口**。本地开发服务器（如 Vite）必须配置 `strictPort: true`（端口被占用时直接报错，严禁自动顺延切换到 5174 等其他端口，避免因浏览器同源策略隔离导致看到空数据库）。
- **申请持久存储**：首次启动调用 `navigator.storage.persist()` 向浏览器申请持久存储，降低被浏览器自动清理的风险。
- **写入时机**：每次操作或页内防抖立即写入 IndexedDB；写入失败时顶部显示红条并提供"导出备份"入口。
- **软删除与自动垃圾回收**：删除操作打上 `deleted_at` 时间戳，支持 5 秒内点击"撤销"恢复；所有统计查询自动过滤 `deleted_at !== null` 的数据。**每次应用启动及执行"导出备份"前，自动物理清除 `deleted_at` 早于 1 小时前的软删除记录**，防止废数据长期堆积污染备份文件。
- **版本号**：数据库带结构版本号；以后升级结构时，旧数据必须能自动迁移，不得丢失。
- **不联网**：运行期间不发起任何外部网络请求（禁止使用外链 CDN 字体或图标），字体、图标全部本地打包提供。

### 7.2 备份（导出）

- 设置页"导出备份"生成一个 **JSON 文件**，包含全部有效数据、应用标识（`app: "evan-app"`）、结构版本号（`schema_version: 1`）、导出时间（`exported_at`）。
- 文件名：`evan-backup-年月日-时分.json`。
- 导出成功后记录"上次备份时间"并显示在设置页。
- 超过 7 天未备份（或从未备份且已有数据满 7 天），首页提示条提醒。

### 7.3 恢复（导入）

流程：选择文件 → 校验 JSON 格式、应用标识（`evan-app`）和版本号 → 显示摘要（导出时间、各类记录数量）→ 提示"将覆盖当前数据" → 确认 → **覆盖前自动触发下载一份当前数据的备份文件** → 事务性写入导入数据。

- 文件格式、应用标识或版本不对时，拒绝导入并给出明确原因，**不改动现有数据**。
- 导入过程若发生异常回滚事务，现有数据保持原样。

### 7.4 清空

需要手动输入"清空"二字才能执行；执行前提示用户先导出备份。

## 11. 假设与默认决定

以下是在确认过程中采用的最终决定，作为第一版开发基准：

1. 验收浏览器为 Chrome 或 Edge 最新版。
2. 保存机制采用"弹窗表单点保存确认 + 页内编辑与一键操作即时自动保存"，不设页面离开拦截。
3. 计划页待办转时间块第一版用"安排时间"按钮与表单，鼠标拖拽排程留到 v1.2。
4. 书的封面用色块加首字，不使用图片。
5. 复盘包含三项状态打分（评分星级、心情表情、精力格，均支持再次点击取消）和三栏文字（做得好的、要改进的、明天最重要的一件事）。
6. 第一版导出只做 JSON，CSV 以后再加。
7. 首页始终显示"今天"，不随顶栏日期变化。
